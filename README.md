# .github

Shared repository scaffolding: a repository template and reusable workflows.

## New repository

Create a new repository from this one with **Use this template**, then:

1. Set `name` in [pyproject.toml](pyproject.toml) and run `uv lock`.
2. Set up the clone as described in [CONTRIBUTING.md](CONTRIBUTING.md#setup).
3. Switch to the shared workflows: replace each workflow in `.github/workflows/` with its caller from
   [workflow-templates/](workflow-templates/), then delete `workflow-templates/` and its entry in
   [dependabot.yaml](.github/dependabot.yaml).
4. In [.cliff.toml](.cliff.toml), set `include_paths` to what the repository releases, or remove it to release every
   change.
5. Replace this README and [LICENSE](LICENSE) with ones for the new repository.

> [!NOTE]
> Changes made here don't reach repositories already created from this template: a template is copied once, with no link
> back. The reusable workflows are the exception: repositories call them by version, and Dependabot proposes each new
> version.

## Workflows

Other repositories call these workflows by version. Copy the caller from [workflow-templates/](workflow-templates/),
which Dependabot keeps on the latest release. Each workflow lists its inputs and their defaults under `workflow_call`;
set them with `with:` on the job that calls it.

Each workflow checks out the calling repository and runs that repository's own tools at the versions in its `uv.lock`,
uv included, so the repository needs the files listed in its section.

> [!CAUTION]
> Leave `concurrency` out of calling workflows. Each workflow sets its own, and a matching group in the caller cancels
> the run.

### Lint

[lint.yaml](.github/workflows/lint.yaml) runs the same pre-commit checks as `just lint`. It needs:

- `pyproject.toml` with the following dev dependencies, locked in `uv.lock`:
  - `uv`
  - `pre-commit`
  - `pre-commit-uv` (optional), to install the Python hooks faster
- `.pre-commit-config.yaml`

### PR Title

[pr-title.yaml](.github/workflows/pr-title.yaml) checks that the pull request title follows Conventional Commits, since
squash merges turn it into the commit on `main`. It runs again when the title is edited. It needs:

- `pyproject.toml` with the following dev dependencies, locked in `uv.lock`:
  - `uv`
  - `pre-commit`
  - `pre-commit-uv` (optional), to install the Python hooks faster
- `.pre-commit-config.yaml` with the `conventional-pre-commit` hook

### Release

[release.yaml](.github/workflows/release.yaml) publishes a release with notes generated by git-cliff when a merge to
`main` calls for one under the repository's `.cliff.toml`, linking each pull request. Its caller grants
`contents: write`, which publishing the release needs. It needs:

- `pyproject.toml` with the following dev dependencies, locked in `uv.lock`:
  - `uv`
  - `git-cliff`
- `.cliff.toml`
